Chapter 3: Formatted Input/Output

3.2 The scanf Function (scanf 함수)

printf가 지정된 형식으로 출력을 인쇄하는 것처럼, scanf는 특정 형식에 따라 입력을 읽습니다. scanf 형식 문자열은 printf 형식 문자열과 마찬가지로 일반 문자와 변환 지정 사양을 모두 포함할 수 있습니다. scanf에서 허용되는 변환은 printf에서 사용되는 것과 본질적으로 동일합니다.

많은 경우 scanf 형식 문자열에는 다음 예제와 같이 변환 지정 사양만 포함됩니다.

int i, j;
float x, y;

scanf("%d%d%d%d", &i, &j, &x, &y);

사용자가 다음 입력 줄을 입력한다고 가정해 봅시다.

1 -20 .3 -4.0e3

scanf는 줄을 읽고, 문자를 숫자로 변환한 다음, 1, -20, 0.3, -4.0e3(즉, -4000.0)을 각각 i, j, x, y에 할당합니다. "%d%d%d%d"와 같이 "빽빽하게 채워진(tightly packed)" 형식 문자열은 scanf 호출에서 흔히 볼 수 있습니다. 반면 printf 형식 문자열은 인접한 변환 지정 사양을 가지는 경우가 적습니다.

scanf는 printf와 마찬가지로 부주의한 사용자를 위한 몇 가지 함정을 포함하고 있습니다. scanf를 사용할 때 프로그래머는 변환 지정 사양의 수가 입력 변수의 수와 일치하는지, 각 변환이 해당 변수에 적합한지 확인해야 합니다. printf와 마찬가지로 컴파일러가 불일치 가능성을 확인하도록 요구되지 않습니다. 또 다른 함정은 scanf 호출에서 각 변수 앞에 오는 & 기호와 관련이 있습니다. &는 보통(항상은 아니지만) 필요하며, 이를 기억하는 것은 프로그래머의 책임입니다.

⚠️ 경고: scanf 호출에서 변수 앞에 & 기호를 넣는 것을 잊으면 예측할 수 없고 잠재적으로 치명적인 결과를 초래할 수 있습니다.

프로그램 충돌이 흔한 결과입니다. 최소한 입력에서 읽은 값이 변수에 저장되지 않고, 대신 변수는 이전 값을 유지합니다(변수가 초기 값을 부여받지 않았다면 의미가 없을 수 있습니다). &를 생략하는 것은 매우 흔한 실수이므로 주의하세요! 일부 컴파일러는 이 오류를 발견하고 "format argument is not a pointer"와 같은 경고 메시지를 생성할 수 있습니다.

scanf 호출은 강력하지만 용서가 없는 데이터 읽기 방법입니다. 많은 전문 C 프로그래머들은 scanf를 피하고, 대신 모든 데이터를 문자 형태로 읽은 다음 나중에 숫자 형태로 변환합니다. 우리는 특히 이 책의 초반 장에서 숫자를 읽는 간단한 방법을 제공하기 때문에 scanf를 꽤 많이 사용할 것입니다. 그러나 많은 프로그램이 사용자가 예상치 못한 입력을 입력하면 제대로 작동하지 않는다는 점을 유의하세요. 나중에 보겠지만, 프로그램이 scanf가 요청된 데이터를 성공적으로 읽었는지 테스트하는 것(그리고 실패할 경우 복구를 시도하는 것)이 가능합니다. 그러한 테스트는 이 책의 프로그램에는 비실용적입니다. 너무 많은 명령문을 추가하여 예제의 요점을 모호하게 만들 것이기 때문입니다.

How scanf Works (scanf의 작동 방식)

scanf는 실제로 지금까지 설명한 것보다 훨씬 더 많은 일을 할 수 있습니다. 기본적으로 입력 문자 그룹을 변환 지정 사양과 일치시키려고 시도하는 "패턴 매칭(pattern-matching)" 함수입니다.

printf 함수와 마찬가지로 scanf는 형식 문자열에 의해 제어됩니다. 호출되면 scanf는 문자열의 정보 처리를 왼쪽에서 시작합니다. 형식 문자열의 각 변환 지정 사양에 대해 scanf는 입력 데이터에서 적절한 타입의 항목을 찾으려고 시도하며, 필요한 경우 공백을 건너뜁니다. 그런 다음 scanf는 항목을 읽고, 항목에 속할 수 없는 문자를 만나면 중지합니다. 항목이 성공적으로 읽히면 scanf는 형식 문자열의 나머지 부분을 계속 처리합니다. 항목이 성공적으로 읽히지 않으면 scanf는 형식 문자열의 나머지 부분(또는 나머지 입력 데이터)을 보지 않고 즉시 반환합니다.

숫자의 시작을 찾을 때 scanf는 공백 문자(공백, 수평 및 수직 탭, 폼 피드, 개행 문자)를 무시합니다. 결과적으로 숫자는 한 줄에 넣거나 여러 줄에 걸쳐 분산시킬 수 있습니다. 다음 scanf 호출을 고려해 보세요.

scanf("%d%d%f%f", &i, &j, &x, &y);

사용자가 세 줄의 입력을 입력한다고 가정해 봅시다.

1
-20  .3
-4.0e3

scanf는 이를 하나의 연속된 문자 스트림으로 봅니다.

••1¤-20••.3¤-4.0e3¤

(•는 공백 문자를, ¤는 개행 문자를 나타냅니다.) 각 숫자의 시작을 찾을 때 공백 문자를 건너뛰기 때문에 scanf는 숫자를 성공적으로 읽을 수 있습니다.

정수나 부동 소수점 숫자를 인식하기 위해 scanf는 어떤 규칙을 따를까요? 정수를 읽으라고 요청받으면 scanf는 먼저 숫자, 더하기 기호 또는 빼기 기호를 검색한 다음 숫자가 아닌 문자에 도달할 때까지 숫자를 읽습니다. 부동 소수점 숫자를 읽으라고 요청받으면 scanf는 (선택적) 더하기 또는 빼기 기호, (소수점을 포함할 수 있는) 일련의 숫자, 그리고 (선택적) 지수를 찾습니다. 지수는 문자 e(또는 E), 선택적 기호, 하나 이상의 숫자로 구성됩니다. scanf와 함께 사용할 때 %e, %f, %g 변환은 서로 교환 가능합니다. 세 가지 모두 부동 소수점 숫자를 인식하는 데 동일한 규칙을 따릅니다.

scanf가 현재 항목의 일부가 될 수 없는 문자를 만나면, 그 문자는 다음 입력 항목의 스캔 중에 또는 다음 scanf 호출 중에 다시 읽히도록 "되돌려집니다(put back)".

Ordinary Characters in Format Strings (형식 문자열의 일반 문자)

패턴 매칭의 개념은 변환 지정 사양 외에 일반 문자를 포함하는 형식 문자열을 작성함으로써 한 단계 더 나아갈 수 있습니다. scanf가 형식 문자열의 일반 문자를 처리할 때 취하는 조치는 그것이 공백 문자인지 아닌지에 따라 달라집니다.

  • 공백 문자(White-space characters): 형식 문자열에서 하나 이상의 연속된 공백 문자를 만나면 scanf는 공백이 아닌 문자(다시 "되돌려짐")에 도달할 때까지 입력에서 공백 문자를 반복해서 읽습니다. 형식 문자열의 공백 문자 수는 중요하지 않습니다. 형식 문자열의 공백 문자 하나는 입력의 모든 수의 공백 문자와 일치합니다. (덧붙여, 형식 문자열에 공백 문자를 넣는다고 해서 입력에 공백 문자가 반드시 있어야 하는 것은 아닙니다.)
  • 기타 문자(Other characters): 형식 문자열에서 공백이 아닌 문자를 만나면 scanf는 이를 다음 입력 문자와 비교합니다. 두 문자가 일치하면 scanf는 입력 문자를 버리고 형식 문자열 처리를 계속합니다. 문자가 일치하지 않으면 scanf는 문제가 되는 문자를 입력에 다시 넣은 다음 형식 문자열의 추가 처리를 중단하거나 입력에서 문자를 읽지 않고 중단합니다.

예를 들어, 형식 문자열이 "%d/%d"라고 가정해 봅시다. 입력이 다음과 같다면

•5/•96

scanf는 정수를 찾는 동안 첫 번째 공백을 건너뛰고, %d를 5와 일치시키고, /를 /와 일치시키고, 다른 정수를 찾는 동안 공백을 건너뛰고, %d를 96과 일치시킵니다.

반면에 입력이 다음과 같다면

•5/•96

scanf는 공백 하나를 건너뛰고, %d를 5와 일치시킨 다음, 형식 문자열의 /를 입력의 공백과 일치시키려고 시도합니다. 일치하지 않으므로 scanf는 공백을 다시 넣고, •/•96 문자는 다음 scanf 호출에서 읽을 수 있도록 남겨둡니다. 첫 번째 숫자 뒤에 공백을 허용하려면 형식 문자열 "%d /%d"를 대신 사용해야 합니다.

Confusing printf with scanf (printf와 scanf 혼동하기)

scanf와 printf 호출은 비슷해 보일 수 있지만 두 함수 사이에는 상당한 차이가 있습니다. 이러한 차이를 무시하면 프로그램의 건강에 해로울 수 있습니다.

흔한 실수 중 하나는 printf 호출에서 변수 앞에 &를 넣는 것입니다.

printf("%d %d\n", &i, &j);    /*** WRONG ***/

다행히 이 실수는 발견하기가 매우 쉽습니다. printf는 i와 j의 값 대신 이상하게 보이는 숫자 몇 개를 표시할 것입니다.

scanf는 데이터 항목을 찾을 때 일반적으로 공백 문자를 건너뛰기 때문에, 형식 문자열에 변환 지정 사양 외의 문자를 포함할 필요가 없는 경우가 많습니다. scanf 형식 문자열이 printf 형식 문자열과 비슷해야 한다고 잘못 가정하는 것(또 다른 흔한 오류)은 scanf가 예상치 못한 방식으로 작동하게 만들 수 있습니다. 다음 scanf 호출이 실행될 때 어떤 일이 발생하는지 살펴보겠습니다.

scanf("%d, %d", &i, &j);

scanf는 먼저 입력에서 정수를 찾아 변수 i에 저장합니다. 그런 다음 scanf는 다음 입력 문자와 쉼표를 일치시키려고 시도합니다. 다음 입력 문자가 쉼표가 아닌 공백이면 scanf는 j 값을 읽지 않고 종료됩니다.

printf 형식 문자열은 종종 \n으로 끝나지만, scanf 형식 문자열 끝에 개행 문자를 넣는 것은 일반적으로 좋지 않은 생각입니다. scanf에게 형식 문자열의 개행 문자는 공백과 동일합니다. 둘 다 scanf가 다음 비공백 문자로 이동하도록 합니다. 예를 들어 형식 문자열이 "%d\n"이면 scanf는 공백을 건너뛰고 정수를 읽은 다음 다음 비공백 문자로 건너뜁니다. 이와 같은 형식 문자열은 대화형 프로그램이 사용자가 비공백 문자를 입력할 때까지 "멈추게(hang)" 할 수 있습니다.

PROGRAM: Adding Fractions (분수 더하기)

패턴을 일치시키는 scanf의 능력을 설명하기 위해 사용자가 입력한 분수를 읽는 문제를 고려해 보겠습니다. 분수는 관례적으로 분자/분모 형태로 작성됩니다. 사용자가 분수의 분자와 분모를 별도의 정수로 입력하는 대신, scanf를 사용하면 전체 분수를 읽을 수 있습니다. 두 분수를 더하는 다음 프로그램은 이 기술을 보여줍니다.

addfrac.c

/* Adds two fractions */

#include <stdio.h>

int main(void)
{
    int num1, denom1, num2, denom2, result_num, result_denom;

    printf("Enter first fraction: ");
    scanf("%d/%d", &num1, &denom1);

    printf("Enter second fraction: ");
    scanf("%d/%d", &num2, &denom2);

    result_num = num1 * denom2 + num2 * denom1;
    result_denom = denom1 * denom2;
    printf("The sum is %d/%d\n", result_num, result_denom);

    return 0;
}

이 프로그램과의 세션은 다음과 같은 모양을 가질 수 있습니다.

Enter first fraction: 5/6
Enter second fraction: 3/4
The sum is 38/24

결과 분수는 기약분수(가장 낮은 항)로 약분되지 않는다는 점에 유의하세요.

💡 Q & A

*Q: 정수를 읽고 쓰기 위해 %i 변환을 본 적이 있습니다. %d와 %i의 차이점은 무엇인가요?
A: printf 형식 문자열에서는 둘 사이에 차이가 없습니다. 그러나 scanf 형식 문자열에서 %d는 10진수(10진법) 형식으로 작성된 정수만 일치시킬 수 있는 반면, %i는 8진수(8진법), 10진수 또는 16진수(16진법)로 표현된 정수를 일치시킬 수 있습니다. 입력 숫자에 0 접두사(예: 056)가 있으면 %i는 이를 8진수로 처리합니다. 0x 또는 0X 접두사(예: 0x56)가 있으면 %i는 이를 16진수로 처리합니다. 숫자를 읽을 때 %d 대신 %i를 사용하면 사용자가 실수로 숫자 시작 부분에 0을 넣으면 놀라운 결과를 초래할 수 있습니다. 이러한 함정 때문에 %d를 고수하는 것이 좋습니다.

Q: printf가 %를 변환 지정 사양의 시작으로 처리한다면 % 문자는 어떻게 인쇄할 수 있나요?
A: printf가 형식 문자열에서 두 개의 연속된 % 문자를 만나면 단일 % 문자를 인쇄합니다.

Q: scanf가 숫자를 읽으라고 요청받았지만 사용자가 숫자가 아닌 입력을 입력하면 어떻게 되나요?
A: scanf가 2와 3을 읽고 23을 저장한 다음 나머지 문자(foo)를 다음 scanf에서 읽을 수 있도록 남겨둡니다. 처음부터 잘못된 입력(예: foo)이면 변수 값은 정의되지 않고 foo는 다음 scanf를 위해 남겨집니다. 나중에 scanf 호출이 성공했는지 테스트하는 방법을 배울 것입니다.

Q: scanf가 문자를 "되돌려 놓고" 나중에 다시 읽는 방법을 이해하지 못하겠습니다.
A: 밝혀진 바에 따르면 프로그램은 입력된 대로 사용자 입력을 읽지 않습니다. 대신 입력은 숨겨진 버퍼에 저장되며 scanf가 액세스할 수 있습니다. scanf가 이후 읽기를 위해 문자를 버퍼에 다시 넣는 것은 쉽습니다. 22장에서 입력 버퍼링에 대해 더 자세히 설명합니다.

Q: 사용자가 숫자 사이에 구두점(예: 쉼표)을 넣으면 scanf는 어떻게 하나요?
A: scanf는 4를 읽어 i에 저장합니다. 두 번째 숫자의 시작을 찾을 때 scanf는 쉼표를 만납니다. 숫자는 쉼표로 시작할 수 없으므로 scanf는 즉시 반환합니다. 쉼표와 두 번째 숫자는 다음 scanf 호출을 위해 남겨집니다. 물론 숫자가 항상 쉼표로 구분된다고 확신하는 경우 형식 문자열에 쉼표를 추가하여 문제를 쉽게 해결할 수 있습니다.

📝 Section 3.2 Summary (써머리)

  • scanf는 형식 문자열을 기반으로 입력을 읽는 "패턴 매칭" 함수입니다.
  • 변수를 전달할 때 & (주소 연산자)를 붙여야 합니다. (문자열 배열 제외)
  • 숫자를 읽을 때 앞의 공백은 무시하지만, 숫자가 아닌 문자를 만나면 해당 문자를 되돌려 놓고(unget) 즉시 반환합니다.
  • 형식 문자열에 \n을 넣으면 예기치 않게 입력을 기다리며 멈출 수 있으므로 주의해야 합니다.
  • %d는 10진수만 읽지만, %i는 8진수, 10진수, 16진수를 모두 읽을 수 있습니다.

✍️ Section 3.2 Exercises (문제) & 정답

  1. 다음 printf 호출이 생성하는 출력은 무엇인가요? (공백은 •로 표시)
    (a) printf("%6d,%4d", 86, 1040);
    (b) printf("%12.5e", 30.253);
    (c) printf("%.4f", 83.162);
    (d) printf("%-6.2g", .0000009979);
    정답:
    (a) ••••86,1040 (86은 너비 6에서 오른쪽 정렬, 1040은 너비 4에 딱 맞음)
    (b) •3.02530e+01 (총 12자리, 소수점 이하 5자리)
    (c) 83.1620 (소수점 이하 4자리)
    (d) 1e-06••• (%g는 유효 숫자 2자리까지만 표시. 0.0000009979는 1.0e-06으로 반올림됨. 왼쪽 정렬이므로 뒤에 공백)
  2. 다음 형식으로 float 변수 x를 표시하는 printf 호출을 작성하세요.
    (a) 지수 표기법, 필드 크기 8에서 왼쪽 정렬, 소수점 이하 1자리
    (b) 지수 표기법, 필드 크기 10에서 오른쪽 정렬, 소수점 이하 6자리
    (c) 고정 소수점 표기법, 필드 크기 8에서 왼쪽 정렬, 소수점 이하 3자리
    (d) 고정 소수점 표기법, 필드 크기 6에서 오른쪽 정렬, 소수점 이하 0자리
    정답:
    (a) printf("%-8.1e", x);
    (b) printf("%10.6e", x);
    (c) printf("%-8.3f", x);
    (d) printf("%6.0f", x);
  3. 다음 scanf 형식 문자열 쌍이 서로 동등한지 확인하세요.
    (a) "%d" vs " %d"
    (b) "%d-%d-%d" vs "%d -%d -%d"
    (c) "%f" vs "%f "
    (d) "%f,%f" vs "%f, %f"
    정답:
    (a) 동등함 (둘 다 앞의 공백을 무시함)
    (b) 동등함 (형식 문자열의 공백은 0개 이상의 공백을 의미하므로)
    (c) 동등하지 않음! "%f "는 숫자를 읽은 후 공백이 아닌 문자를 만날 때까지 기다리기 때문에 사용자가 추가 입력을 할 때까지 프로그램이 멈출 수 있음.
    (d) 동등함 (쉼표 뒤의 공백은 무시됨)
  4. scanf("%d%f%d", &i, &x, &j);를 호출하고 사용자가 10.3 5 6을 입력하면 i, x, j의 값은 어떻게 되나요?
    정답: i = 10, x = 0.3, j = 5
    (이유: %d가 10을 읽고, %f가 .3을 읽음. 그 다음 %d가 5를 읽고, 6은 남겨둠)
  5. scanf("%f%d%d", &x, &i, &y);를 호출하고 사용자가 12.3 45.6 789를 입력하면 x, i, y의 값은 어떻게 되나요?
    정답: x = 12.3, i = 45, y = 할당되지 않음(쓰레기 값)
    (이유: %d가 45를 읽은 뒤 '.'을 만나서 중단됨. y에 값을 할당하지 못함)
  6. Section 3.2의 addfrac.c 프로그램을 수정하여 사용자가 분수 사이에 공백을 넣을 수 있도록 하려면 어떻게 해야 할까요? (예: 5 / 6)
    정답: scanf 형식 문자열에 공백을 추가합니다.
    scanf("%d / %d", &num1, &denom1);
    scanf("%d / %d", &num2, &denom2);
    (형식 문자열의 공백은 입력의 0개 이상의 공백을 의미하므로, 공백이 있든 없든 모두 읽을 수 있습니다.)

🔥 형광칠한 핵심 내용 총정리 (Highlights)

Section 3.2에서 형광펜으로 강조한 가장 중요한 내용들을 한눈에 볼 수 있도록 연계하여 정리했습니다. scanf는 C 언어에서 가장 위험하고 까다로운 함수 중 하나이므로, 다음 규칙을 반드시 기억하세요.

  • 1. & (주소 연산자)의 절대적 필요성:
    scanf는 입력받은 값을 변수에 저장하기 위해 변수의 메모리 주소를 알아야 합니다. 따라서 변수 이름 앞에 반드시 &를 붙여야 합니다. (printf와 혼동하여 &를 붙이면 안 됩니다.)
  • 2. 패턴 매칭과 "되돌려 놓기(unget)":
    scanf는 입력 스트림에서 원하는 형식을 찾을 때까지 문자를 읽고, 형식에 맞지 않는 문자를 만나면 읽기를 중단하고 해당 문자를 입력 버퍼에 다시 되돌려 놓습니다. 이는 다음 scanf 호출에서 그 문자를 다시 읽을 수 있게 하기 위함입니다.
  • 3. 공백의 처리와 \n의 위험성:
    scanf는 숫자를 읽기 전에 앞의 공백을 무시합니다. 하지만 형식 문자열에 \n을 넣는 것은 "공백이 아닌 문자를 만날 때까지 기다리라"는 의미이므로, 대화형 프로그램에서 예상치 못한 멈춤(hang) 현상을 유발할 수 있습니다.
  • 4. printf와 scanf의 형식 문자열 차이:
    printf에서는 변수를 값으로 전달하고, scanf에서는 주소로 전달합니다. 또한 scanf의 형식 문자열에서 공백은 "0개 이상의 공백"을 의미하므로, 입력 데이터의 유연성을 위해 적절히 활용해야 합니다.
