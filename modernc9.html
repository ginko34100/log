Chapter 6: Loops

"5장에서는 C의 선택문인 if와 switch를 다루었습니다. 이 장에서는 반복(looping)을 설정할 수 있게 해주는 C의 반복문(iteration statements)을 소개합니다." - 앨런 펄리스

루프는 다른 명령문(루프 본문, loop body)을 반복적으로 실행하는 것이 임무인 명령문입니다. C에서 모든 루프에는 제어 수식(controlling expression)이 있습니다. 루프 본문이 실행될 때마다(루프의 한 번의 반복, iteration) 제어 수식이 평가됩니다. 수식이 참(0이 아닌 값)이면 루프가 계속 실행됩니다.

C는 세 가지 반복문을 제공합니다: while, do, for입니다. while 문은 루프 본문이 실행되기 전에 제어 수식을 테스트하는 루프에 사용됩니다. do 문은 루프 본문이 실행된 후에 수식을 테스트하는 경우에 사용됩니다. for 문은 카운팅 변수를 증가시키거나 감소시키는 루프에 편리합니다. 6.3절에서는 주로 for 문에서 사용되는 쉼표 연산자(comma operator)도 소개합니다.

이 장의 마지막 두 절은 루프와 함께 사용되는 C 기능에 할애됩니다. 6.4절에서는 break, continue, goto 문을 설명합니다. break는 루프를 빠져나와 루프 다음 명령문으로 제어를 전환하고, continue는 루프 반복의 나머지 부분을 건너뛰며, goto는 함수 내의 모든 명령문으로 점프합니다. 6.5절에서는 본문이 비어 있는 루프를 만드는 데 사용할 수 있는 널 문(null statement)을 다룹니다.

6.1 The while Statement (while 문)

C에서 루프를 설정하는 모든 방법 중에서 while 문이 가장 간단하고 기본적입니다. while 문은 다음과 같은 형태를 가집니다.

while (expression) statement

괄호 안의 수식은 제어 수식(controlling expression)이고, 괄호 뒤의 명령문은 루프 본문(loop body)입니다. 다음은 예입니다.

while (i < n)    /* controlling expression */
    i = i * 2;   /* loop body */

괄호는 필수이며, 오른쪽 괄호와 루프 본문 사이에는 아무것도 오지 않습니다. (일부 언어에서는 do라는 단어가 필요합니다.)

while 문이 실행되면 제어 수식이 먼저 평가됩니다. 값이 0이 아니면(참) 루프 본문이 실행되고 수식이 다시 테스트됩니다. 이 과정은 제어 수식이 결국 0 값을 가질 때까지 계속됩니다.

다음 예제는 while 문을 사용하여 n보다 크거나 같은 2의 가장 작은 거듭제곱을 계산합니다.

i = 1;
while (i < n)
    i = i * 2;

n의 값이 10이라고 가정해 봅시다. while 문이 실행될 때 일어나는 일을 추적해 보겠습니다.

  • i = 1; → i는 이제 1입니다.
  • i < n인가? 예; 계속합니다.
  • i = i * 2; → i는 이제 2입니다.
  • i < n인가? 예; 계속합니다.
  • ... (반복) ...
  • i = i * 2; → i는 이제 16입니다.
  • i < n인가? 아니오; 루프를 종료합니다.

제어 수식(i < n)이 참인 동안 루프가 계속되는 방식에 주목하세요. 수식이 거짓이 되면 루프가 종료되고 원하는 대로 i가 n보다 크거나 같아집니다.

루프 본문은 단일 명령문이어야 하지만, 이는 기술적인 문제일 뿐입니다. 여러 개의 명령문을 원한다면 중괄호를 사용하여 단일 복합문을 만들면 됩니다.

while (i > 0) {
    printf("T minus %d and counting\n", i);
    i--;
}

Infinite Loops (무한 루프)

while 문은 제어 수식이 항상 0이 아닌 값을 가지면 종료되지 않습니다. 실제로 C 프로그래머들은 때때로 0이 아닌 상수를 제어 수식으로 사용하여 의도적으로 무한 루프를 만듭니다.

while (1) ...

이 형태의 while 문은 본문에 제어를 루프 밖으로 전환하는 명령문(break, goto, return)이 포함되어 있거나 프로그램 종료를 유발하는 함수를 호출하지 않는 한 영원히 실행됩니다.

PROGRAM: Printing a Table of Squares (제곱표 출력하기)

제곱표를 출력하는 프로그램을 작성해 보겠습니다. 이 프로그램은 먼저 사용자에게 숫자 n을 입력하라는 메시지를 표시합니다. 그런 다음 n개의 출력 줄을 인쇄하며, 각 줄에는 1에서 n 사이의 숫자와 그 제곱이 포함됩니다.

square.c

/* Prints a table of squares using a while statement */

#include <stdio.h>

int main(void)
{
    int i, n;

    printf("This program prints a table of squares.\n");
    printf("Enter number of entries in table: ");
    scanf("%d", &n);

    i = 1;
    while (i <= n) {
        printf("%10d%10d\n", i, i * i);
        i++;
    }

    return 0;
}

square.c가 숫자를 깔끔하게 정렬된 열로 표시하는 방식을 주목하세요. 비결은 단순히 %d 대신 %10d와 같은 변환 지정 사양을 사용하여 필드 너비를 지정할 때 printf가 숫자를 오른쪽 정렬한다는 사실을 활용하는 것입니다.

6.2 The do Statement (do 문)

do 문은 while 문과 밀접한 관련이 있습니다. 실제로 do 문은 기본적으로 루프 본문이 실행된 후에 제어 수식이 테스트되는 while 문입니다. do 문은 다음과 같은 형태를 가집니다.

do statement while (expression);

while 문과 마찬가지로 do 문의 본문은 하나의 명령문이어야 하며(물론 복합문도 가능), 제어 수식은 괄호로 묶어야 합니다.

do 문이 실행되면 루프 본문이 먼저 실행되고 제어 수식이 평가됩니다. 수식의 값이 0이 아니면 루프 본문이 다시 실행되고 수식이 다시 평가됩니다. do 문의 실행은 루프 본문이 실행된 후 제어 수식이 0 값을 가질 때 종료됩니다.

6.1절의 카운트다운 예제를 이번에는 do 문을 사용하여 다시 작성해 보겠습니다.

i = 10;
do {
    printf("T minus %d and counting\n", i);
    --i;
} while (i > 0);

do 문이 실행되면 루프 본문이 먼저 실행되어 "T minus 10 and counting" 메시지가 인쇄되고 i가 감소합니다. 이제 조건 i > 0이 테스트됩니다. 9는 0보다 크므로 루프 본문이 두 번째로 실행됩니다. 이 과정은 "T minus 1 and counting" 메시지가 인쇄되고 i가 0이 될 때까지 계속됩니다. 이제 테스트 i > 0이 실패하여 루프가 종료됩니다. 이 예제에서 알 수 있듯이 do 문은 종종 while 문과 구별할 수 없습니다. 두 문장의 차이점은 do 문의 본문은 항상 적어도 한 번은 실행된다는 것입니다. 제어 수식이 처음에 0이면 while 문의 본문은 완전히 건너뛰게 됩니다.

PROGRAM: Calculating the Number of Digits in an Integer (정수의 자릿수 계산하기)

while 문이 C 프로그램에서 do 문보다 훨씬 자주 나타나지만, 후자는 적어도 한 번은 실행되어야 하는 루프에 유용합니다. 이 점을 설명하기 위해 사용자가 입력한 정수의 자릿수를 계산하는 프로그램을 작성해 보겠습니다.

우리의 전략은 사용자의 입력을 0이 될 때까지 반복해서 10으로 나누는 것입니다. 수행된 나눗셈의 수가 자릿수가 됩니다. 0에 도달하는 데 몇 번의 나눗셈이 걸릴지 모르기 때문에 어떤 종류의 루프가 필요하다는 것은 분명합니다. 하지만 while 문을 사용해야 할까요, 아니면 do 문을 사용해야 할까요? 모든 정수(0을 포함)는 적어도 하나의 자릿수를 가지므로 do 문이 더 매력적입니다.

numdigits.c

/* Calculates the number of digits in an integer */

#include <stdio.h>

int main(void)
{
    int digits = 0, n;

    printf("Enter a nonnegative integer: ");
    scanf("%d", &n);

    do {
        n /= 10;
        digits++;
    } while (n > 0);

    printf("The number has %d digit(s).\n", digits);

    return 0;
}

6.3 The for Statement (for 문)

이제 C의 마지막 루프인 for 문에 도달했습니다. for 문의 겉보기 복잡성에 낙담하지 마세요. 사실 많은 루프를 작성하는 가장 좋은 방법입니다. for 문은 "카운팅" 변수가 있는 루프에 이상적이지만 다른 종류의 루프에도 사용할 수 있을 만큼 다재다능합니다.

for 문은 다음과 같은 형태를 가집니다.

for (expr1; expr2; expr3) statement

여기서 expr1, expr2, expr3는 수식입니다. 다음은 예입니다.

for (i = 10; i > 0; i--)
    printf("T minus %d and counting\n", i);

이 for 문이 실행되면 변수 i가 10으로 초기화된 다음 i가 0보다 큰지 테스트합니다. 0보다 크므로 "T minus 10 and counting" 메시지가 인쇄된 다음 i가 감소합니다. 그런 다음 조건 i > 0이 다시 테스트됩니다. 루프 본문은 i가 10에서 1로 변하면서 총 10번 실행됩니다.

for Statement Idioms (for 문의 관용구)

for 문은 일반적으로 "카운트 업(증가)" 또는 "카운트 다운(감소)"하는 루프에 가장 적합합니다. n번 카운트 업 또는 다운하는 for 문은 일반적으로 다음 형태 중 하나를 가집니다.

  • 0에서 n-1까지 카운트 업: for (i = 0; i < n; i++) ...
  • 1에서 n까지 카운트 업: for (i = 1; i <= n; i++) ...
  • n-1에서 0까지 카운트 다운: for (i = n - 1; i >= 0; i--) ...
  • n에서 1까지 카운트 다운: for (i = n; i > 0; i--) ...

이 패턴을 모방하면 초보 C 프로그래머가 자주 범하는 다음과 같은 실수를 피하는 데 도움이 됩니다.

  • 제어 수식에서 < 대신 >를 사용하는 경우(또는 그 반대의 경우). "카운트 업" 루프는 < 또는 <= 연산자를 사용하는 반면, "카운트 다운" 루프는 > 또는 >=를 사용합니다.
  • 제어 수식에서 <, <=, >, >= 대신 ==를 사용하는 경우.
  • i <= n 대신 i < n으로 작성하는 것과 같은 "오프 바이 원(off-by-one)" 오류.

Omitting Expressions in a for Statement (for 문에서 수식 생략하기)

for 문은 지금까지 본 것보다 훨씬 더 유연합니다. 일부 for 루프는 일반적으로 루프를 제어하는 세 가지 수식이 모두 필요하지 않을 수 있으므로 C에서는 수식을 생략할 수 있습니다.

첫 번째 수식을 생략하면 루프가 실행되기 전에 초기화가 수행되지 않습니다. 세 번째 수식을 생략하면 루프 본문이 두 번째 수식의 값이 결국 거짓이 되도록 보장해야 합니다. 두 번째 수식을 생략하면 기본값이 참이므로 for 문이 종료되지 않습니다(다른 방식으로 중지되지 않는 한).

일부 프로그래머는 무한 루프를 설정하기 위해 다음 for 문을 사용합니다.

for (;;) ...

for Statements in C99 (C99의 for 문)

C99에서는 for 문의 첫 번째 수식을 선언으로 대체할 수 있습니다. 이 기능을 사용하면 프로그래머가 루프에서 사용할 변수를 선언할 수 있습니다.

for (int i = 0; i < n; i++) ...

변수 i는 이 명령문 이전에 선언될 필요가 없습니다. (실제로 i의 선언이 이미 존재하는 경우 이 명령문은 루프 내에서만 사용될 i의 새 버전을 생성합니다.) for 문에 의해 선언된 변수는 루프 본문 외부에서 액세스할 수 없습니다.

The Comma Operator (쉼표 연산자)

때때로 우리는 두 개 이상의 초기화 수식이 있는 for 문을 작성하거나 루프를 통해 매번 여러 변수를 증가시키는 문을 작성하고 싶을 수 있습니다. for 문의 첫 번째 또는 세 번째 수식으로 쉼표 수식(comma expression)을 사용하여 이를 수행할 수 있습니다.

쉼표 수식은 expr1, expr2 형태를 가집니다. 쉼표 수식은 두 단계로 평가됩니다. 먼저 expr1이 평가되고 그 값은 버려집니다. 둘째, expr2가 평가되고 그 값이 전체 수식의 값이 됩니다. expr1을 평가하면 항상 부작용이 있어야 합니다. 그렇지 않으면 expr1은 아무 목적도 없습니다.

예를 들어 i와 j의 값이 각각 1과 5라고 가정해 봅시다. 쉼표 수식 ++i, i + j가 평가되면 i가 먼저 증가한 다음 i + j가 평가되므로 수식의 값은 7입니다. (물론 i는 이제 2입니다.) 쉼표 연산자의 우선순위는 다른 모든 연산자보다 낮으므로 ++i와 i + j 주위에 괄호를 넣을 필요가 없습니다.

6.4 Exiting from a Loop (루프에서 빠져나오기)

우리는 루프 본문 이전에 종료 지점이 있는 루프(while 및 for 문 사용) 또는 이후에 종료 지점이 있는 루프(do 문 사용)를 작성하는 방법을 보았습니다. 그러나 때로는 루프 중간에 종료 지점이 있는 루프가 필요할 수 있습니다. 루프에 둘 이상의 종료 지점이 있기를 원할 수도 있습니다. break 문을 사용하면 두 종류의 루프를 모두 작성할 수 있습니다.

The break Statement (break 문)

break 문이 switch 문에서 제어를 전환하는 방법에 대해서는 이미 논의했습니다. break 문은 while, do, for 루프에서 빠져나오는 데도 사용할 수 있습니다.

n이 소수인지 확인하는 프로그램을 작성한다고 가정해 봅시다. 우리의 계획은 n을 2에서 n-1 사이의 숫자로 나누는 for 문을 작성하는 것입니다. 약수를 찾는 즉시 루프에서 빠져나와야 합니다(break). 나머지 가능성을 시도할 필요가 없습니다.

for (d = 2; d < n; d++)
    if (n % d == 0)
        break;

if (d < n)
    printf("%d is divisible by %d\n", n, d);
else
    printf("%d is prime\n", n);

break 문은 종료 지점이 본문의 시작이나 끝이 아닌 중간에 있는 루프를 작성하는 데 특히 유용합니다. 특정 값이 입력될 때 종료되는 사용자 입력을 읽는 루프는 종종 이 범주에 속합니다.

for (;;) {
    printf("Enter a number (enter 0 to stop): ");
    scanf("%d", &n);
    if (n == 0)
        break;
    printf("%d cubed is %d\n", n, n * n * n);
}

break 문은 가장 안쪽에 있는 while, do, for 또는 switch 문 밖으로 제어를 전환합니다. 따라서 이러한 문장들이 중첩되어 있을 때 break 문은 오직 한 단계의 중첩만 벗어날 수 있습니다.

The continue Statement (continue 문)

continue 문은 실제로 루프를 빠져나가지 않기 때문에 여기에 속하지는 않습니다. 하지만 break와 유사하기 때문에 이 섹션에 포함시키는 것이 완전히 임의적이지는 않습니다. break는 루프 끝 바로 다음으로 제어를 전환하는 반면, continue는 루프 본문의 끝 바로 전 지점으로 제어를 전환합니다. break의 경우 제어가 루프를 떠나고, continue의 경우 제어는 루프 내부에 남아 있습니다. break와 continue 사이에는 또 다른 차이점이 있습니다. break는 switch 문과 루프(while, do, for)에서 사용할 수 있지만, continue는 루프로 제한됩니다.

다음 예제는 일련의 숫자를 읽고 그 합계를 계산하는 간단한 continue 사용법을 보여줍니다. 0이 아닌 숫자 10개를 읽으면 루프가 종료됩니다. 숫자 0을 읽을 때마다 continue 문이 실행되어 루프 본문의 나머지 부분(sum += i; 및 n++;)을 건너뛰고 루프 내부에 남아 있습니다.

n = 0;
sum = 0;
while (n < 10) {
    scanf("%d", &i);
    if (i == 0)
        continue;
    sum += i;
    n++;    /* continue jumps to here */
}

The goto Statement (goto 문)

break와 continue는 프로그램의 한 지점에서 다른 지점으로 제어를 전환하는 점프 문입니다. 둘 다 제한적입니다. break의 대상은 둘러싸는 루프 끝 바로 다음 지점이고, continue의 대상은 루프 끝 바로 전 지점입니다. 반면에 goto 문은 명령문에 레이블이 있는 경우 함수의 모든 명령문으로 점프할 수 있습니다.

레이블은 명령문 시작 부분에 배치된 식별자일 뿐입니다. goto 문 자체는 goto identifier; 형태를 가집니다. goto L; 문을 실행하면 제어가 레이블 L 뒤에 오는 명령문으로 전환됩니다. goto 문은 일상적인 C 프로그래밍에서는 거의 필요하지 않습니다. break, continue, return 문(본질적으로 제한적으로 확장된 goto 문) 및 exit 함수는 다른 언어에서 goto가 필요할 수 있는 대부분의 상황을 처리하기에 충분합니다.

6.5 The Null Statement (널 문)

C에는 명령문이 필요하지만 수행할 작업이 없는 상황이 있습니다. 이 경우 널 문(null statement)을 사용합니다. 널 문은 세미콜론(;)만 있는 명령문입니다.

널 문은 주로 루프에서 사용되며, 루프 본문을 비워두어야 하는 경우에 사용됩니다. 예를 들어, n이 소수인지 확인하는 루프를 다시 생각해 봅시다. n % d == 0 조건을 루프의 제어 수식으로 이동하면 루프 본문이 비게 됩니다.

for (d = 2; d < n && n % d != 0; d++)
    /* empty loop body */ ;

널 문은 한 줄에 따로 배치하는 것이 관례입니다. 그렇지 않으면 for 뒤에 오는 명령문이 실제 루프 본문인지 혼동할 수 있기 때문입니다.

⚠️ 경고: if, while, for 문의 괄호 뒤에 실수로 세미콜론을 넣으면 널 문이 생성되어 if, while, for 문이 조기에 종료됩니다.

while 문에서 괄호 뒤에 세미콜론을 넣으면 무한 루프가 생성될 수 있습니다.

i = 10;
while (i > 0);    /*** WRONG ***/
{
    printf("T minus %d and counting\n", i);
    --i;
}

for 문에서 괄호 뒤에 세미콜론을 넣으면 루프 본문이 되어야 할 명령문이 루프가 종료된 후 한 번만 실행됩니다.

for (i = 10; i > 0; i--);    /*** WRONG ***/
    printf("T minus %d and counting\n", i);

이 예제는 "T minus 0 and counting" 메시지를 인쇄합니다.

💡 Chapter 6 Q&A (질의응답)

Q: 6.1절의 루프는 왜 "> 0" 테스트를 제거하여 더 단축하지 않나요?
A: 새 버전이 더 간결하고 많은 C 프로그래머가 이렇게 작성하지만 단점이 있습니다. 첫째, 새 루프가 원래 루프만큼 읽기 쉽지 않습니다. 둘째, 루프가 시작될 때 i가 음수 값을 가지면 새 루프는 다르게 동작합니다. 원래 루프는 즉시 종료되지만 새 루프는 그렇지 않습니다.

Q: while (1)과 for (;;) 중 어느 형태의 무한 루프가 더 선호되나요?
A: C 프로그래머들은 전통적으로 효율성 때문에 for (;;)를 선호해 왔습니다. 오래된 컴파일러는 종종 while 루프를 통과할 때마다 프로그램이 1 조건을 테스트하도록 강제했습니다. 그러나 최신 컴파일러에서는 성능 차이가 없어야 합니다.

Q: 프로그래머가 continue 문을 절대 사용해서는 안 된다고 들었습니다. 사실인가요?
A: continue 문이 드문 것은 사실입니다. 그래도 continue는 때때로 유용합니다. 입력 데이터를 읽고 유효성을 검사하는 루프를 작성한다고 가정해 봅시다. 유효성 검사 테스트가 여러 개 있거나 복잡한 경우 continue가 도움이 될 수 있습니다.

Q: goto 문의 문제점은 무엇인가요?
A: goto 문은 본질적으로 악한 것은 아니며, 단지 우리가 보통 더 나은 대안을 가지고 있을 뿐입니다. goto 문을 너무 많이 사용하는 프로그램은 빠르게 "스파게티 코드"로 변질되어 제어가 이리저리 점프할 수 있습니다. 스파게티 코드는 이해하고 수정하기 어렵습니다.

📝 Chapter 6 Summary (써머리)

  • while 문은 조건을 먼저 검사하고, 참이면 본문을 실행합니다. 조건이 처음부터 거짓이면 본문은 한 번도 실행되지 않습니다.
  • do 문은 본문을 먼저 실행하고 조건을 나중에 검사합니다. 따라서 본문은 최소한 한 번은 무조건 실행됩니다.
  • for 문은 초기화, 조건, 증감을 한 곳에 모아 카운팅 루프를 작성하기에 가장 편리합니다. C99에서는 for 문 안에서 변수를 선언할 수 있습니다.
  • break는 루프를 완전히 빠져나가고, continue는 현재 반복의 나머지를 건너뛰고 다음 조건 검사로 넘어갑니다.
  • 실수로 while이나 for 문 뒤에 세미콜론(;)을 붙이면 널 문이 되어 논리 오류를 유발합니다.

  1. 다음 프로그램 조각이 출력하는 결과는 무엇인가요? 
    i = 1;
while (i <= 128) {
    printf("%d ", i);
    i *= 2;
}
    정답: 1 2 4 8 16 32 64 128
  2. 다음 프로그램 조각이 출력하는 결과는 무엇인가요? 
    i = 9384;
do {
    printf("%d ", i);
    i /= 10;
} while (i > 0);
    정답: 9384 938 93 9
  3. 다음 for 문이 출력하는 결과는 무엇인가요? 
    for (i = 5, j = i - 1; i > 0, j > 0; --i, j = i - 1)
    printf("%d ", i);
    정답: 5 4 3 2 1
    (이유: 조건식 i > 0, j > 0은 쉼표 연산자이므로 오른쪽 값인 j > 0만 루프 제어에 사용됩니다. i=5, j=4일 때 시작해서 --i, j=i-1에 의해 i가 1씩 줄어듭니다.)
  4. 다음 중 나머지 둘과 동등하지 않은 문장은 무엇인가요? (루프 본문은 동일하다고 가정)
    (a) for (i = 0; i < 10; i++) ...
    (b) for (i = 0; i < 10; ++i) ...
    (c) for (i = 0; i++ < 10; ) ...
    정답: (c)
    (이유: (c)는 조건 검사 후에 i가 증가하므로 루프 본문이 실행되는 동안 i의 값이 (a), (b)와 다를 수 있습니다. 특히 루프가 끝난 후 i의 값이 다릅니다.)
  5. 다음 중 나머지 둘과 동등하지 않은 문장은 무엇인가요?
    (a) while (i < 10) {...}
    (b) for (; i < 10;) {...}
    (c) do {...} while (i < 10);
    정답: (c)
    (이유: (a)와 (b)는 조건을 먼저 검사하는 반면, (c)는 본문을 먼저 실행합니다. 따라서 i가 처음에 10 이상이면 (a), (b)는 실행되지 않지만 (c)는 한 번 실행됩니다.)
  6. 다음 for 문을 동등한 while 문으로 변환하세요. 
    for (i = 10; i >= 1; i /= 2)
    printf("%d ", i++);
    정답:
    i = 10;
while (i >= 1) {
    printf("%d ", i++);
    i /= 2;
}
    (주의: for 문의 세 번째 수식은 루프 본문이 실행된 후에 실행되므로 while 문에서는 본문 끝에 넣어야 합니다.)

🔥 형광칠한 핵심 내용 총정리 (Highlights)

Chapter 6에서 형광펜으로 강조한 가장 중요한 내용들을 한눈에 볼 수 있도록 연계하여 정리했습니다. 반복문은 프로그램의 실행 흐름을 제어하는 핵심이므로, 다음 4가지 규칙을 반드시 기억하세요.

  • 1. while vs do-while의 결정적 차이:
    while은 조건을 먼저 검사하므로 조건이 거짓이면 본문이 0번 실행될 수 있습니다. do-while은 본문을 먼저 실행하므로 최소 1번은 무조건 실행됩니다. "자릿수 계산"처럼 최소 1번은 실행되어야 하는 경우 do-while이 적합합니다.
  • 2. for 문의 강력함과 유연성:
    for 문은 초기화, 조건, 증감을 한 곳에 모아 카운팅 루프를 직관적으로 작성할 수 있습니다. for (;;)를 사용하면 무한 루프를 만들 수 있으며, 쉼표 연산자를 활용해 여러 변수를 동시에 제어할 수도 있습니다.
  • 3. break vs continue의 명확한 차이:
    break는 루프(또는 switch)를 완전히 탈출하여 다음 명령문으로 넘어갑니다. continue는 루프를 탈출하지 않고, 현재 반복의 나머지 부분을 건너뛴 뒤 다음 조건 검사(또는 for 문의 증감식)로 넘어갑니다.
  • 4. 치명적인 실수: 널 문(Null Statement)의 함정:
    while (i > 0);나 for (i = 0; i < 10; i++);처럼 괄호 뒤에 실수로 세미콜론(;)을 붙이면, 그 뒤의 명령문은 루프 본문이 아닌 별개의 명령문이 됩니다. 이는 무한 루프나 의도치 않은 결과를 초래합니다.
