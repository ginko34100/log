Chapter 2: C Fundamentals

2.7 Identifiers (식별자)

프로그램을 작성할 때, 우리는 변수, 함수, 매크로 및 기타 엔티티에 이름을 선택해야 합니다. 이러한 이름을 식별자(Identifiers)라고 합니다. C에서 식별자는 문자, 숫자 및 밑줄(underscore, _)을 포함할 수 있지만, 반드시 문자나 밑줄로 시작해야 합니다. (C99에서는 식별자에 "보편 문자 이름(universal character names)"이 포함될 수 있습니다.)

다음은 올바른 식별자의 몇 가지 예입니다.

times10    get_next_char    _done

다음은 올바르지 않은 식별자입니다.

10times    get-next-char

기호 10times는 숫자로 시작하기 때문에 올바르지 않습니다. get-next-char는 밑줄이 아닌 빼기 기호(minus sign)를 포함하고 있습니다.

C는 대소문자를 구분(case-sensitive)합니다. 즉, 식별자에서 대문자와 소문자를 구별합니다. 예를 들어, 다음 식별자들은 모두 다릅니다.

job    joB    jOb    jOB    Job    JoB    JOb    JOB

이 여덟 개의 식별자는 각각 완전히 다른 목적을 위해 동시에 사용될 수 있습니다. (난해함에 대해 말하자면!) 현명한 프로그래머는 관련이 없는 한 식별자가 다르게 보이도록 노력합니다.

C에서는 대소문자가 중요하므로, 많은 프로그래머들이 식별자(매크로 제외)에 소문자만 사용하고 가독성을 위해 필요할 때 밑줄을 삽입하는 관례를 따릅니다.

symbol_table    current_page    name_and_address

다른 프로그래머들은 밑줄을 피하고 대신 식별자 내에서 각 단어를 시작할 때 대문자를 사용합니다.

symbolTable    currentPage    nameAndAddress

(첫 글자도 대문자로 쓰기도 합니다.) 전자의 스타일이 전통적인 C에서 흔하지만, Java와 C#(그리고 덜하지만 C++)에서 널리 사용되기 때문에 후자의 스타일이 더 대중화되고 있습니다. 다른 합리적인 관례들도 존재합니다. 프로그램에서 식별자가 나타날 때마다 항상 같은 방식으로 대문자/소문자를 사용해야 합니다.

C는 식별자의 최대 길이에 제한을 두지 않으므로 길고 설명적인 이름을 사용하는 것을 두려워하지 마세요. current_page와 같은 이름은 cp와 같은 이름보다 이해하기 훨씬 쉽습니다.

C의 대소문자 구분 때문에, 키워드는 표 2.1에 표시된 대로 정확하게 프로그램에 나타나야 하며, 모든 문자가 소문자여야 합니다. 표준 라이브러리의 함수 이름(예: printf)도 소문자만 포함합니다. 전체 프로그램을 대문자로 입력했다가 컴파일러가 키워드와 라이브러리 함수 호출을 인식하지 못하는 불행한 프로그래머의 처지를 피하세요.

⚠️ 경고: 식별자에 대한 다른 제한 사항을 주의하세요. 일부 컴파일러는 특정 식별자(예: asm)를 추가 키워드로 취급합니다. 표준 라이브러리에 속한 식별자도 제한됩니다. 이러한 이름 중 하나를 실수로 사용하면 컴파일 또는 링크 중에 오류가 발생할 수 있습니다. 밑줄로 시작하는 식별자도 제한됩니다.

2.8 Layout of a C Program (C 프로그램의 레이아웃)

우리는 C 프로그램을 일련의 토큰(Tokens)으로 생각할 수 있습니다. 토큰은 의미를 변경하지 않고는 분할할 수 없는 문자 그룹입니다. 식별자와 키워드는 토큰입니다. + 및 -와 같은 연산자, 쉼표 및 세미콜론과 같은 구두점, 문자열 리터럴도 토큰입니다. 예를 들어, 다음 명령문은

printf("Height: %d\n", height);

일곱 개의 토큰으로 구성됩니다.

printf ( "Height: %d\n" , height ) ;

토큰 ①과 ⑤는 식별자, 토큰 ③은 문자열 리터럴, 토큰 ②, ④, ⑥, ⑦은 구두점입니다.

대부분의 경우 프로그램에서 토큰 사이의 공백 양은 중요하지 않습니다. 극단적으로 말하면, 두 개의 토큰이 세 번째 토큰으로 병합되는 경우를 제외하고는 토큰 사이에 공간 없이 서로 밀집시킬 수 있습니다. 예를 들어, int와 main 사이, float와 fahrenheit 사이에 공간을 남겨두는 한 celsius.c 프로그램의 대부분의 공간을 삭제할 수 있습니다.

사실 페이지가 더 넓다면 전체 main 함수를 한 줄에 넣을 수도 있습니다. 하지만 전체 프로그램을 한 줄에 넣을 수는 없습니다. 각 전처리 지시어는 별도의 줄을 필요로 하기 때문입니다.

이런 식으로 프로그램을 압축하는 것은 좋은 생각이 아닙니다. 사실 공백과 빈 줄을 추가하면 프로그램을 더 쉽게 읽고 이해할 수 있습니다. 다행히도 C는 토큰 사이에 원하는 만큼의 공백(공백, 탭, 개행 문자)을 삽입할 수 있도록 허용합니다. 이 규칙은 프로그램 레이아웃에 몇 가지 중요한 영향을 미칩니다.

  • 명령문은 여러 줄에 걸쳐 나눌 수 있습니다. 예를 들어, 다음 명령문은 너무 길어서 한 줄에 넣기 어렵습니다. 
    printf("Dimensional weight (pounds): %d\n", (volume + INCHES_PER_POUND - 1) / INCHES_PER_POUND);
  • 토큰 사이의 공백은 눈이 토큰을 분리하기 쉽게 만듭니다. 이러한 이유로 저는 보통 각 연산자 앞뒤에 공백을 둡니다. 
    volume = height * length * width;
    각 쉼표 뒤에도 공백을 둡니다. 일부 프로그래머는 더 나아가 괄호와 기타 구두점 주위에 공백을 둡니다.
  • 들여쓰기(Indentation)는 중첩(nesting)을 더 쉽게 찾을 수 있게 합니다. 예를 들어, 선언과 명령문을 들여쓰기하여 main 안에 중첩되어 있음을 명확히 해야 합니다.
  • 빈 줄(Blank lines)은 프로그램을 논리적 단위로 나누어 독자가 프로그램의 구조를 더 쉽게 식별할 수 있게 합니다. 빈 줄이 없는 프로그램은 장(chapter)이 없는 책만큼 읽기 어렵습니다.

2.6절의 celsius.c 프로그램은 이러한 지침 중 몇 가지를 보여줍니다. 해당 프로그램의 main 함수를 자세히 살펴보겠습니다.

int main(void)
{
    float fahrenheit, celsius;

    printf("Enter Fahrenheit temperature: ");
    scanf("%f", &fahrenheit);

    celsius = (fahrenheit - FREEZING_PT) * SCALE_FACTOR;

    printf("Celsius equivalent: %.1f\n", celsius);

    return 0;
}

먼저 =, -, * 주변의 공백이 이러한 연산자를 어떻게 돋보이게 하는지 관찰하세요. 둘째, 선언과 명령문의 들여쓰기가 이들이 모두 main에 속해 있음을 어떻게 명백하게 만드는지 주목하세요. 마지막으로, 빈 줄이 main을 다섯 부분으로 나누는 방식을 주목하세요. (1) fahrenheit 및 celsius 변수 선언, (2) 화씨 온도 얻기, (3) celsius 값 계산, (4) 섭씨 온도 출력, (5) 운영체제로 반환.

프로그램 레이아웃에 대해 말하자면, 제가 { 토큰을 main () 아래에 배치하고 일치하는 }를 별도의 줄에 {와 정렬하여 배치한 방식을 주목하세요. }를 별도의 줄에 두면 함수 끝에 명령문을 삽입하거나 삭제할 수 있으며, {와 정렬하면 main의 끝을 쉽게 찾을 수 있습니다.

마지막으로, 토큰 사이에 여분의 공백을 추가할 수 있지만, 프로그램의 의미를 변경하거나 오류를 일으키지 않고 토큰 내부에 공백을 추가하는 것은 불가능합니다. 다음과 같이 작성하면

fl oat fahrenheit, celsius;    /*** WRONG ***/

또는

fl
oat fahrenheit, celsius;    /*** WRONG ***/

프로그램을 컴파일할 때 오류가 발생합니다. 문자열 리터럴 내부에 공백을 넣는 것은 허용되지만 문자열의 의미가 변경됩니다. 그러나 문자열에 개행 문자를 넣는 것(즉, 문자열을 두 줄에 걸쳐 나누는 것)은 불법입니다.

printf("To C, or not to C:
that is the question.\n");    /*** WRONG ***/

한 줄에서 다음 줄로 문자열을 계속하려면 나중 장에서 배울 특별한 기술이 필요합니다.

📝 Section 2.7 - 2.8 Summary (써머리)

  • 식별자(Identifier)는 문자, 숫자, 밑줄로 구성되며 문자나 밑줄로 시작해야 합니다. C는 대소문자를 엄격히 구분합니다.
  • 키워드(Keyword)는 C 언어에서 예약된 단어(예: int, return)이므로 식별자로 사용할 수 없습니다.
  • C 프로그램은 토큰(Token)의 집합이며, 토큰 사이의 공백, 탭, 줄바꿈은 컴파일러가 무시합니다.
  • 가독성을 위해 연산자 주변에 공백을 두고, 적절한 들여쓰기와 빈 줄을 사용하는 것이 좋습니다.
  • 토큰 내부에 공백을 넣거나, 문자열 리터럴을 두 줄에 걸쳐 나누면 오류가 발생합니다.

🔥 형광칠한 핵심 내용 총정리 (Highlights)

Section 2.7과 2.8에서 형광펜으로 강조한 가장 중요한 내용들을 한눈에 볼 수 있도록 연계하여 정리했습니다. 이 부분은 앞으로 여러분이 작성할 모든 C 코드의 기본 규칙이 됩니다.

  • 1. 식별자의 명명 규칙:
    식별자는 문자 또는 밑줄(_)로 시작해야 하며, 숫자로 시작할 수 없습니다. 또한 C는 대소문자를 구분하므로 job과 Job은 완전히 다른 이름입니다. 이 규칙은 변수 이름을 지을 때 가장 기본이 되며, 실수로 숫자로 시작하는 이름을 지으면 컴파일 오류가 발생합니다.
  • 2. 키워드와의 충돌 방지:
    C 언어가 이미 사용하고 있는 키워드(예: int, return, if)는 식별자로 사용할 수 없습니다. 또한 키워드는 반드시 소문자로 작성해야 합니다. (대문자 INT는 키워드가 아닙니다.)
  • 3. 토큰(Token)의 개념:
    C 프로그램은 의미를 나눌 수 없는 최소 단위인 '토큰'으로 구성됩니다. 컴파일러는 토큰 사이의 공백, 탭, 줄바꿈을 무시하므로 프로그래머는 가독성을 위해 자유롭게 공백을 넣을 수 있습니다.
  • 4. 가독성을 위한 레이아웃:
    토큰 사이에 공백을 넣는 것은 자유롭지만, 토큰 내부(예: fl oat)에 공백을 넣거나 문자열 리터럴을 두 줄로 나누면 오류가 발생합니다. 연산자 주변에 공백을 두고, 들여쓰기와 빈 줄을 사용하여 프로그램의 구조를 명확히 하는 것이 좋은 코딩 스타일입니다.
