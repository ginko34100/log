2.1 Writing a Simple Program (간단한 프로그램 작성)

어떤 언어로 작성된 프로그램과 달리, C 프로그램은 "상용구(boilerplate)"가 거의 필요하지 않습니다. 완전한 프로그램은 단 몇 줄에 불과할 수 있습니다.

PROGRAM (프로그램): 말장난 출력하기 (Printing a Pun)

커니핸(Kernighan)과 리치(Ritchie)의 고전 The C Programming Language에 나오는 첫 번째 프로그램은 매우 짧습니다. 단지 hello, world라는 메시지를 출력할 뿐입니다. 다른 C 저자들과 달리, 저는 이 프로그램을 첫 번째 예제로 사용하지 않겠습니다. 대신 C의 또 다른 전통인 '나쁜 말장난(bad pun)'을 지키겠습니다. 여기 말장난이 있습니다:

To C, or not to C: that is the question.

다음 프로그램은 우리가 pun.c라고 이름 붙일 것이며, 실행될 때마다 이 메시지를 표시합니다.

pun.c

#include <stdio.h>

int main(void)
{
    printf("To C, or not to C: that is the question.\n");
    return 0;
}

2.2절에서 이 프로그램의 형태를 다소 자세히 설명하겠습니다. 지금은 몇 가지만 간략히 살펴보겠습니다.

  • #include <stdio.h> 줄은 C의 표준 I/O(입출력) 라이브러리에 대한 정보를 "포함(include)"하는 데 필요합니다.
  • 프로그램의 실행 가능한 코드는 main 내부에 들어갑니다. 이는 "메인(main)" 프로그램을 나타냅니다.
  • main 내부의 유일한 줄은 원하는 메시지를 표시하라는 명령입니다. printf는 표준 I/O 라이브러리의 함수로, 출력 형식을 멋지게 지정할 수 있습니다.
  • \n 코드는 메시지를 출력한 후 다음 줄로 이동하라고 printf에 지시합니다.
  • return 0; 줄은 프로그램이 종료될 때 운영체제에 값 0을 "반환(return)"함을 나타냅니다.

Compiling and Linking (컴파일과 링크)

짧음에도 불구하고, pun.c를 실행시키는 것은 생각보다 복잡합니다. 먼저, 프로그램을 포함하는 pun.c라는 파일을 생성해야 합니다(아무 텍스트 편집기나 사용 가능). 파일 이름은 중요하지 않지만, 컴파일러는 종종 .c 확장자를 요구합니다.

다음으로, 프로그램을 기계가 실행할 수 있는 형태로 변환해야 합니다. C 프로그램의 경우, 일반적으로 세 단계를 거칩니다:

  1. 전처리(Preprocessing): 프로그램은 먼저 전처리기(preprocessor)로 전달되며, 전처리기는 #으로 시작하는 명령(지시어, directive)을 따릅니다. 전처리기는 편집기와 비슷합니다. 프로그램에 내용을 추가하거나 수정할 수 있습니다.
  2. 컴파일(Compiling): 수정된 프로그램은 이제 컴파일러로 전달되며, 컴파일러는 이를 기계어 명령(오브젝트 코드, object code)으로 번역합니다. 하지만 이 프로그램은 아직 실행할 준비가 되지 않았습니다.
  3. 링크(Linking): 마지막 단계에서 링커(linker)가 컴파일러가 생성한 오브젝트 코드를 완전한 실행 가능한 프로그램을 만드는 데 필요한 추가 코드와 결합합니다. 이 추가 코드에는 프로그램에서 사용되는 라이브러리 함수(예: printf)가 포함됩니다.

다행히도 이 과정은 종종 자동화되어 있어 그렇게 번거롭지 않을 것입니다. 실제로 전처리기는 보통 컴파일러와 통합되어 있으므로 작업하는 것을 눈치채지 못할 수도 있습니다.

컴파일 및 링크에 필요한 명령은 컴파일러와 운영체제에 따라 다릅니다. UNIX에서는 C 컴파일러의 이름이 보통 cc입니다. pun.c 프로그램을 컴파일하고 링크하려면 터미널이나 명령줄 창에 다음 명령을 입력합니다:

% cc pun.c

(% 문자는 UNIX 프롬프트이며, 입력할 필요가 없습니다.) cc를 사용할 때 링크는 자동으로 수행되므로 별도의 링크 명령이 필요하지 않습니다.

프로그램을 컴파일하고 링크한 후 cc는 기본적으로 a.out이라는 파일에 실행 가능한 프로그램을 남깁니다. cc에는 많은 옵션이 있습니다. 그중 하나(-o 옵션)를 사용하면 실행 파일을 포함하는 파일의 이름을 선택할 수 있습니다. 예를 들어 pun.c의 실행 버전 이름을 pun으로 지정하려면 다음 명령을 입력합니다:

% cc -o pun pun.c

The GCC Compiler (GCC 컴파일러)

가장 인기 있는 C 컴파일러 중 하나는 Linux와 함께 제공되지만 다른 많은 플랫폼에서도 사용할 수 있는 GCC 컴파일러입니다. 이 컴파일러를 사용하는 것은 전통적인 UNIX cc 컴파일러를 사용하는 것과 유사합니다. 예를 들어 pun.c 프로그램을 컴파일하려면 다음 명령을 사용합니다:

% gcc -o pun pun.c

GCC에 대한 자세한 내용은 이 장 끝의 Q&A 섹션에서 제공합니다.

Integrated Development Environments (통합 개발 환경)

지금까지 우리는 운영체제에서 제공하는 특수 창에 명령을 입력하여 호출되는 "명령줄(command-line)" 컴파일러의 사용을 가정했습니다. 대안은 통합 개발 환경(IDE)을 사용하는 것입니다. IDE는 환경을 떠나지 않고도 프로그램을 편집, 컴파일, 링크, 실행 및 디버깅할 수 있는 소프트웨어 패키지입니다. IDE의 구성 요소는 함께 작동하도록 설계되었습니다. 예를 들어 컴파일러가 프로그램에서 오류를 감지하면 편집기가 오류가 포함된 줄을 강조 표시하도록 준비할 수 있습니다. IDE마다 매우 다양한 변형이 있으므로 이 책에서는 더 이상 논의하지 않겠습니다. 그러나 플랫폼에 사용할 수 있는 IDE가 있는지 확인해 보시기를 권장합니다.

📝 Section 2.1 Summary (써머리)

  • C 프로그램은 #include와 같은 전처리 지시어, main과 같은 함수, 그리고 세미콜론(;)으로 끝나는 명령문으로 구성됩니다.
  • 프로그램은 전처리(Preprocessing) → 컴파일(Compiling) → 링크(Linking)의 3단계를 거쳐 실행 파일이 됩니다.
  • UNIX/Linux 환경에서는 cc 또는 gcc 명령어를 사용하여 컴파일하며, -o 옵션으로 실행 파일 이름을 지정할 수 있습니다.
  • printf는 화면에 문자열을 출력하는 표준 라이브러리 함수이며, \n은 줄바꿈(개행)을 의미합니다.

  2. C 프로그램이 실행 가능한 파일이 되기까지 거치는 세 가지 단계(전처리, 컴파일, 링크)를 순서대로 나열하고, 각 단계에서 어떤 일이 일어나는지 간략히 설명하세요.
  3. 다음 중 UNIX/Linux 환경에서 C 소스 코드를 컴파일하고 실행 파일 이름을 my_program으로 지정하는 올바른 명령어는 무엇인가요?
    (a) cc my_program.c
    (b) gcc -o my_program my_program.c
    (c) cc -o my_program.c my_program
